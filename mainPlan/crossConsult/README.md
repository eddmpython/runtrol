# crossConsult

상태: 대기. 선행은 `desktopGui` (M1, 토글이 살 표면) 와 두 실물 드라이버 (M0) 다.

## 한 문장 정의

**토글 하나로 두 CLI 가 서로를 공식 표면 (MCP) 으로 등록해, 한 AI 가 턴 중에 다른 AI 의 의견을 직접 받아온다.** 북극성 `AI 끼리 서로 자문` 축이 이 이니셔티브다.

## 왜 이것이 runtrol 의 것인가

"여러 AI 를 한 곳에서" 의 다음 문장이다. 한 목록에서 보는 것 (M0~M1) 을 넘어, 그 AI 들이 한 팀이 되게 한다. 벤더는 구조적으로 못 한다 (Claude 앱이 Codex 를 등록해 줄 이유가 없다). 경쟁 OSS 도 이 배선을 제품 표면으로 가진 곳이 없다.

교차 자문 자체는 CLI 가 이미 할 줄 안다: Claude Code 는 자신을 MCP 서버로 내주고 (`claude mcp serve`), 상대를 MCP 클라이언트로 등록하는 공식 명령을 갖는다. **없는 것은 능력이 아니라 편의다.** 사용자가 MCP 라는 개념을 배우고, 명령 문법을 찾고, 양쪽에 등록하고, 해제를 기억하는 것. 그 마찰을 토글 하나로 삼키는 것이 이 이니셔티브다 (최상위 원칙: "개념을 배워야 하면 실패").

## 얇음 경계 (이것이 설계의 전부다)

| 만진다 | 안 만진다 |
|---|---|
| provider 의 **공식 설정 명령** 실행 (`claude mcp add` 류) | 설정 파일 직접 쓰기 (`configReadOnly` 바닥 게이트 위반) |
| 배선의 존재 여부 표시 (등록됨 / 안 됨) | 자문 대화의 본문 (읽지도, 저장하지도, 중계하지도 않는다) |
| 토글 끔 = 공식 해제 명령으로 원상복구 | 자동 에이전트 루프 (A 출력 -> B 입력 배선은 영구 금지) |

자문 트래픽은 CLI 끼리 직접 오간다 (MCP stdio, 두 프로세스 사이). runtrol 은 그 파이프의 존재만 알고 내용은 모른다. `noTranscriptCopy` · `egressContract` 와 충돌 없음이 성립 조건이다.

## 배선 방법 (발견 사다리 적용)

1. **명령 표면 발견.** `claude mcp --help` 류를 probe 해 등록·해제 명령의 존재와 문법을 런타임에 안다. 하드코딩 금지, [binary-identity cache](../../docs/providerDiscovery.md#probe-cache), drift 는 `agentSurfaceDrift` 계열로 감지.
2. **공식 명령이 없는 provider 는 배선하지 않는다.** 파일 직접 쓰기로 우회하지 않는다 (정공법. `configReadOnly` 가 벽이다). 그 provider 의 토글은 "지원 안 됨 + 이유" 로 보인다.
3. **등록 방향은 대칭이 기본.** A 가 B 를 부르고 B 가 A 를 부른다. 한쪽만 원하면 방향 선택.

## 보안

- 배선 = 에이전트 능력 확장이다. **원격 (폰) 에서 기본 거부.** 토글은 PC 앞 물리 행동으로만 켠다 (`securityPosture` 의 위험 능력 목록에 등재).
- 배선된 상대가 일으키는 위험 작업 승인은 각 CLI 의 기존 permission 흐름 그대로다. runtrol 이 새 승인 경로를 발명하지 않는다.

## 완료 판정

- `crossConsultSmoke`: 토글 켬 -> 실물 두 CLI 상호 등록 -> 한 CLI 가 턴 중 상대 의견을 실제 수신 -> 토글 끔 -> 설정 원상복구. 본문 무통과와 설정 파일 무기록을 같은 스모크에서 단언한다.
- 사용자 여정: MCP 라는 단어를 보지 않고 토글 하나로 켜고 끈다.
