# 포지셔닝 . 왜 runtrol 이 존재하는가

운영자 결정 (2026-08-11): **"한 개의 VS Code 창에서 모든 프로젝트, 세션, 에이전트를 즉시 운영한다" 가 불변 북극성이다.**

이 문장의 뜻은 기능 묶음이 아니다. 다음 일곱 계약을 동시에 지키는 제품만 runtrol 이다.

1. 기능이 늘어도 기다림과 버벅임을 허용하지 않는다
2. 논리 세션 수와 renderer 및 active stream 수를 분리한다
3. 지원되는 설치형 CLI 를 런타임에 자동 발견하고 provider-neutral 하게 운영한다
4. provider agent 가 결박된 저장소를 자율적으로 변경한다
5. 선택한 session 을 정확한 workspace 또는 worktree에 즉시 연결한다
6. 여러 agent 와 background 작업보다 사람의 입력과 편집기가 먼저 반응한다
7. conversation, credential, transcript는 provider가 소유하고 runtrol은 얇은 supervisor로 남는다

## 결정 전에 알아야 했던 것

전문 에이전트 5 인 토론의 가장 중요한 산출은 설계가 아니라 정직한 진단이었다. **"PC 의 코딩 CLI 를 원격에서 다룬다" 만으로는 중복이다.**

| 이미 존재하는 것 | 무엇을 하는가 |
|---|---|
| Anthropic Remote Control (2026-02-24) | 전 요금제 무료. QR 페어링, 세션 목록, 재개, push, `--spawn worktree`, `--capacity 32` |
| OpenAI Codex Remote (Windows 호스트 2026-05-29, GA 06-25) | 같은 것을 Codex 에서 |
| GitHub Copilot CLI · Amp | Amp 는 2026-07-08 부터 원격 새 세션 생성까지 |
| Happy (slopus/happy) 22.9k star | MIT, iOS·Android·web, Claude Code + Codex, E2E, 자체 호스팅 가능 |
| agent-of-empires 2.9k star | 이미 Rust, MIT, PWA, QR 페어링, 10+ CLI 자동 감지 |
| ACP (Agent Client Protocol) v1 | `session/new|list|resume|delete`, Rust SDK, provider manifest 레지스트리 |

**Rust 는 차별점이 아니다.** 이 판의 경쟁자 열 개 이상이 이미 Rust 다.
**"똑똑한 비하드코딩 provider 관리" 도 이미 표준으로 존재한다.** 그래서 ACP 를 채택하고 발명하지 않는다.

상용 레이어는 무덤이다: vibe-kanban (27.5k star, Rust) 2026-04-10 폐업, terragon 폐업, crystal deprecated, omnara v1 deprecated, cui 는 "Anthropic 이 냈다" 며 자진 archive.

## 그래서 고른 자리

**한 개의 VS Code 창에서 여러 provider, session, project를 하나의 즉각적인 작업 맥락으로 운영한다.**

여러 provider 를 하나의 목록에서 보는 것은 이 자리의 필수 바닥이지만 전부가 아니다. 목록에서 session을 고른 즉시 정확한 workspace와 worktree가 연결되고, agent가 저장소를 자율적으로 변경하는 동안에도 사람의 VS Code가 버벅이지 않아야 북극성이 완성된다.

왜 구조적인가:

- **Claude 앱에 Codex 세션은 영원히 안 뜬다.** 벤더가 남의 provider 를 자기 앱에 넣을 이유가 없다
- **목록이 넷으로 갈라지는 것은 기능 차이가 아니다.** 각 벤더가 각자 완벽하게 만들수록 사용자의 파편화는 더 심해진다
- **벤더가 이 문제를 고치면 그건 자기 제품을 남에게 여는 것**이므로, 경쟁 구도상 일어나지 않는다

경쟁자 중에 여러 provider 를 다루는 것 (Happy, agent-of-empires) 은 있다. 그들과의 차이는 **한 곳에서** 라는 말의 범위다: PC 앞의 앱과 폰의 PWA 가 같은 세션 모델을 공유하고, 그 사이에 누구의 서버도 없다.

## 중앙 세션 판단

PTY 하나를 여러 화면에 붙이는 기술 자체는 새 발명이 아니다. 터미널 멀티플렉서와 원격 셸이 오래전부터 해온
일이다. 따라서 "데몬 중앙화" 한 단어를 혁신이라고 부르지 않는다.

runtrol 의 핵심은 다음 조건을 한 계약으로 묶는 데 있다.

1. provider conversation owner 는 대화마다 하나이고, Runtime 은 owner PTY 와 공식 attach renderer 중 증명된 한 중앙 표면의 입력 순서를 소유한다
2. VS Code 창, 원래 터미널, 폰과 공개 SDK 는 그 중앙 출력과 화면을 복제하지 않고 같은 generation 에 붙는다
3. 새 창을 여는 행위는 관찰일 뿐이며 자동 continue 나 resume 을 만들지 않는다
4. broker 밖에서 이미 돌던 세션은 발견 즉시 모든 창의 목록에 나타나며, provider 공식 attach 가 구조적으로 증명되면 같은 TUI 로 붙고, 없으면 원본을 죽이거나 빼앗지 않고 그 터미널을 가진 창을 앞으로 부르거나 (`Focus owner`) 관찰만 한다고 (`Observed only`) 정직하게 말한다
5. provider 가 지은 대화명과 프로젝트 색은 같은 세션을 보는 모든 Studio 표면에서 하나의 신원으로 갱신된다

이 결합이 사용자가 위치를 기억하지 않아도 되는 수준으로 빠르고 안정적으로 작동할 때 제품 혁신에 가깝다.
코드에 중앙 객체가 있다는 사실만으로는 부족하다. 설치와 업데이트 뒤에도 살아 있는 세션이 그대로 보이고,
어느 화면의 입력도 같은 세션에 반영되며, 30개 세션과 여러 창에서도 메모리와 입력 지연 게이트를 지켜야 한다.
그 실물 여정이 깨지면 중앙 설계가 구현돼 있어도 제품은 미완성이다.

## 북극성을 떠받치는 구조적 갭 셋

다음 항목은 북극성의 경계를 더 강하게 만든다. 별도 제품으로 분리하지 않고 북극성 표의 기존 축 안에서 처리한다.

| 갭 | 내용 | 어느 축이 흡수하는가 |
|---|---|---|
| **벤더가 배제한 구성** | Bedrock, Vertex, Foundry, LLM gateway, 사내 프록시, API key 인증, ZDR 조직, `DO_NOT_TRACK`. Anthropic Remote Control 은 claude.ai OAuth 를 요구하므로 이 전부에서 켜지지 않는다. Dispatch 는 Pro/Max 전용, Copilot CLI 원격 제어는 org 정책에 걸린다 | `폰에서 내 PC 세션 잇기` 의 "계정 등급이나 인증 방식이 이 경험을 막지 않는다" |
| **진짜 supervisor 를 가진 headless** | Codex 는 데스크톱 앱이 사실상 필수 브리지이고 headless Linux 는 미해결. Claude 는 프로세스가 죽으면 세션이 끝나서 사용자가 tmux 를 직접 써야 한다 | `끊겨도 살아남기` |
| **tmux 없는 네이티브 Windows** | claude-squad 는 Windows 에서 아예 안 뜬다 (`creack/pty` 미지원). tmux 기반 OSS 전반의 공통 약점. 단 벤더 것들은 Windows 를 지원하므로 OSS 경쟁자에게만 유효하다 | `어디서나 같은 방법` |

## 구조적으로 유리한 사실

Anthropic 이 2026-01 과 04 에 **OAuth 토큰 프록시를 금지**했다. 그런데 **공식 바이너리를 spawn 하는 것은 여전히 허용**된다.

즉 "채팅을 가로채지 않는다" 는 취향이 아니라 **유일하게 살아남는 아키텍처**다. 이 제약을 지키는 제품만 계속 존재할 수 있고, 지키지 않은 것들 (OpenCode 계열) 은 하루아침에 끊겼다.

또: **성숙한 Rust 네이티브 세션 매니저 + 모바일 클라이언트는 존재하지 않는다.** 유일한 진지한 시도 vibe-kanban 은 폐업했고 사유는 기술이 아니라 사업모델이었다 ("압도적 다수가 무료 사용자였고 신날 만한 수익 모델을 못 찾았다"). **오픈소스로 수익을 좇지 않는다면 그 사인은 runtrol 에 해당하지 않는다.**

## 성장 모델 . 품질이 기여를 부른다

운영자 방향 (2026-07-30): **"진짜 좋게 만들면 누구든 기여한다. 성공으로 갈 수 있게 강력하게 만든다."**

이 판의 유일한 사업모델 사망 사례 (vibe-kanban: "신날 만한 수익 모델을 못 찾았다") 에 대한 runtrol 의 답은 수익이 아니라 **기여**다. 호스팅도 계정도 없으므로 지금 파는 것이 없고, 지속가능성은 기여자 에너지에서 온다. 그리고 기여자는 광고가 아니라 품질에 온다.

**라이선스는 그 답을 유지하되 미래를 닫지 않는다** (2026-08-18 결정). 본체는 AGPL-3.0-only, 남이 링크하는 공개 클라이언트 패키지만 Apache-2.0 이다. 이 선택이 하는 일은 두 가지다. 하나, 누구든 포크해서 닫아 파는 경로를 막는다 (MIT 가 유일하게 내주던 권리가 그것이었다). 둘, 저작권을 한 곳에 유지시켜 (`CONTRIBUTING.md` 의 inbound grant) 나중에 상용 판단이 필요해질 때 과거 기여자를 전원 추적하지 않아도 되게 한다. 지금 무엇을 팔지는 정하지 않았고 정할 필요도 없다. 정해야 할 때 정할 수 있는 상태를 유지하는 것이 이 결정의 전부다.

비용도 적어 둔다. 일부 기업은 AGPL 소프트웨어를 사내 정책으로 통째 금지한다. runtrol 은 라이브러리가 아니라 별도 프로세스로 CLI 를 감독하므로 사용자 코드에 의무를 걸지 않지만, 정책은 그 구분을 하지 않는 경우가 있다. 그래서 연동 경로인 클라이언트 패키지는 permissive 로 남기고, 의무 없음을 README 와 NOTICE 에 명시한다.

이 저장소가 기여자에게 보내는 신호는 이미 설계에 들어 있다.

| 신호 | 무엇이 그렇게 만드는가 |
|---|---|
| 이 레포는 자신에게 거짓말하지 않는다 | 정직한 점수판 (게이트 없으면 3 점 상한, 점수는 내려갈 수 있다) |
| 기여해도 회귀 걱정이 없다 | 실패할 수 있음을 스스로 증명하는 게이트 (selftest, ratchet, drift) |
| 무엇이 머지되고 안 되는지 예측 가능하다 | 얇음 원칙의 명확한 경계 (대화에 손대는 PR 은 품질과 무관하게 닫힌다) |
| 왜 이렇게 됐는지 추적 가능하다 | 실측 근거가 남은 설계 문서 (모든 결정에 숫자 또는 소스 독해가 붙어 있다) |
| provider 하나 붙이는 것이 쉽다 | manifest 등록 (ACP CLI 는 TOML 10 줄, Rust 0 줄). **가장 자연스러운 첫 기여 경로다** |

문은 `CONTRIBUTING.md` 가 연다. 품질을 지키는 규율 (게이트, 얇음, 관용구) 은 기여의 장벽이 아니라 기여가 헛되지 않는다는 보증이다.

## 접어야 할 조건 (kill criteria)

미리 적어두지 않으면 접어야 할 때 못 접는다.

1. **벤더 중 하나가 남의 provider 세션을 자기 앱 목록에 넣는다.** 구조적 갭이 사라진다
2. **ACP 가 공용 클라이언트를 낳고 그것이 멀티 provider 목록과 모바일을 둘 다 한다.** 우리가 지을 이유가 없다
3. **자식 바이너리 spawn 이 ToS 로 금지된다.** 아키텍처 자체가 불법이 된다
4. **북극성 `즉시 반응` 과 `상주 비용` 이 6 개월 안에 8 점에 못 간다.** 편의가 없으면 존재 이유가 없다
5. **운영자 본인이 3 개월 이상 안 쓴다.** 스스로 안 쓰는 제품은 완성되지 않는다
6. **한 개의 VS Code 창과 bounded Code-hot workspace가 다중 창 기준선보다 빠르지 않다.** workspace 전환 접근을 버리고 다시 설계한다
7. **세션 수가 늘면서 renderer, full stream, 입력 지연 비용이 함께 늘어난다.** conversation virtualization 접근을 버리고 다시 설계한다

## 인정하고 시작하는 것

**공급자 하나만 쓰는 사람에게 runtrol 은 필요 없다.** README 에 그렇게 적는다. 그렇게 적을 수 있는 제품만이 나머지 사용자에게 믿음을 얻는다.
